Tutorials

From the first launch to an air–water transition, direct thruster control, force telemetry and the reproduction of the paper. Commands match the launch files, topics and services of this repository.

Two terminals. Run source ~/nezha_ws/devel/setup.bash in each. Start Gazebo in terminal A and send commands from terminal B; Ctrl-C in terminal A shuts the simulation down.

TUTORIAL 1

Command a transmedium take-off

Spawn Nezha-Mini in the lake and send the RotorS controller a position above the waterline.

  1. Launch the lake world (terminal A)

    Gazebo starts with the lake, the spectral wave field and the vehicle at the surface.

    roslaunch nezha_gazebo nezha_mini_lake.launch paused:=false

  2. Publish the setpoint (terminal B)

    rostopic pub -r 20 /nezha_mini/command/pose geometry_msgs/PoseStamped \
  '{header: {frame_id: world}, pose: {position: {x: 0.0, y: 0.0, z: 2.0}, orientation: {w: 1.0}}}'
    nezha_mini_takeoff.launch and nezha_mini_wavetakeoff.launch only set up the scene; the setpoint above causes the take-off.

  3. Watch the transition

    rostopic echo /nezha_mini/ground_truth/pose
rosservice call /nezha_mini/transmedia/get_phase_sample "{}"

    position.z crosses the surface_z reported by the service.

TUTORIAL 2

Inspect the triple-domain Husky

Launch the Husky with its ground, aerial and underwater parts, then list what it exposes.

  1. Launch the all-domain Husky

    roslaunch nezha_gazebo nezha_husky_UGV_UAV_UUV.launch
# staged variants
roslaunch nezha_gazebo nezha_husky_pure_UGV.launch   # ground only
roslaunch nezha_gazebo nezha_husky_UGV_UAV.launch    # ground + air
roslaunch nezha_gazebo nezha_husky.launch            # ground + air + underwater

  2. Discover actuators and physics interfaces

    rostopic list | grep -E 'nezha_husky|cmd_vel|thruster|command'
rosservice list | grep -E 'nezha_husky|hydrodynamics|phase'

  3. Compare the variants

    Repeat the listings with the ground-only and ground + air launches to see which interfaces each part adds.

TUTORIAL 3

Drive the underwater thrusters

Command the two surge thrusters directly, then read pose and hydrodynamic forces.

  1. Bring up the lake

    roslaunch nezha_gazebo nezha_mini_lake.launch

  2. Publish moderate, continuous setpoints

    rostopic pub -r 10 /nezha_mini/thrusters/1/input uuv_gazebo_ros_plugins_msgs/FloatStamped "{data: 20.0}" &
rostopic pub -r 10 /nezha_mini/thrusters/2/input uuv_gazebo_ros_plugins_msgs/FloatStamped "{data: 20.0}" &

  3. Inspect and stop

    rosservice call /nezha_mini/get_hydrodynamics_forces "{}"
kill %1 %2
TUTORIAL 4

Read force and phase telemetry (MT)

Transition drag is a ROS topic; the hydrodynamic decomposition and the phase sample are ROS services.

  1. List the force topics and services

    rostopic list | grep -iE 'force|wrench|buoyan|drag|thrust'
rosservice list | grep -iE 'force|hydro|phase'

  2. Read one effect

    rostopic echo /nezha_mini/transmedia_drag
rosservice call /nezha_mini/get_hydrodynamics_forces "{}"
rosservice call /nezha_mini/transmedia/get_phase_sample "{}"

  3. Plot or record

    rosrun rqt_plot rqt_plot      # add /nezha_mini/transmedia_drag/vector/z
rosbag record -O takeoff_forces.bag /nezha_mini/transmedia_drag /nezha_mini/ground_truth/pose
    Services are request–response calls and are not recorded by rosbag. Poll them when you need buoyancy, damping, added mass, Coriolis, wave or phase data.
TUTORIAL 5

Reproduce the results of the paper

The analysis steps need Python 3 with numpy, scipy, pandas and sympy. Run them from the repository root. Each folder has a README with the details.

  1. LEAP and Table IV

    Refits every model on both splits with five seeds (NSE: four propeller configurations; TR: water exit and water entry) and writes sweep_metrics.csv; this takes tens of minutes. Accuracy values match the stored file; inference times are measured again on your machine.

    python3 leap/table_iv/sweep.py /tmp/leap_sweep

    See leap/README.md.

  2. Scenario C metrics (Fig. 11)

    cd experiments/scenario_c
python3 metrics.py results ../../data/fig11_scenarioC

    Prints the summary stored in results/summary.json: mean position error 0.148 m (NezhaSim) and 0.141 m (baseline) over 100 runs each.

  3. PSC closed-loop test (Table V)

    The full-rate odometry and the gzserver log of all 60 runs are stored compressed (odom.csv.xz, launch.log.xz), so the runs can be scored again without the simulator.

    python3 experiments/psc_closed_loop/analyze_batch.py experiments/psc_closed_loop/results /tmp/summary.json
python3 experiments/psc_closed_loop/analyze_timing.py experiments/psc_closed_loop/results psc /tmp/timing_psc.json

    The first command reproduces results/summary.json and Table V; the second the per-step plugin cost (426 µs on average).

  4. Run the simulations again

    Scenario A uses hydro_model:=legacy for its stored runs (Fig. 9 data); Scenario C and the PSC test have batch scripts (Scenario C, PSC test).
